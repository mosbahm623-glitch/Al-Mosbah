# المصباح (Al Mosbah)

تطبيق محاسبة مشاريع التشطيب والفرش. React + Vite + TypeScript + Supabase، ويشتغل على الموبايل كـ PWA.

## تشغيل محلي

```
cp .env.example .env.local   # VITE_SUPABASE_URL و VITE_SUPABASE_PUBLISHABLE_KEY
npm install
npm run dev
```

## الأوامر

| الأمر                       | بيعمل إيه                                                                       |
| --------------------------- | ------------------------------------------------------------------------------- |
| `npm run dev`               | تشغيل محلي                                                                      |
| `npm run quality`           | **كل الفحوصات مرة واحدة** (نفس اللي CI بيشغّله): تنسيق، lint، معمارية، كود ميت، اختبارات، بناء |
| `npm test`                  | الاختبارات (Supabase متحاكى، مفيش اتصال بقاعدة بيانات حقيقية)                    |
| `npm run build`             | فحص الأنواع (TypeScript strict) + بناء                                          |
| `npm run lint`              | oxlint                                                                          |
| `npm run format`            | تنسيق الكود بـ Prettier (`format:check` للفحص بس)                                |
| `npm run architecture:check`| يتأكد إن الصفحات مش بتكلم Supabase مباشرة                                       |
| `npm run knip`              | يكشف الملفات والتصديرات غير المستخدمة                                           |

## هيكل الكود

```
src/
  App.tsx             بوابة الدخول + مسارات الصفحات
  auth/               تسجيل الدخول والـ profile والصلاحيات
  layout/             الهيدر والسايد بار والثيم والمسارات (hash routing)
  components/         مكونات عامة (Dialog, DataGrid, TableReport, EntryDialog...)
  pages/              الصفحات (لوحة التحكم، المشاريع، العهد، البنوك، التقارير، الموافقات، المستخدمين)
  lib/                طبقة البيانات + الحسابات: كل كلام مع Supabase هنا بس
supabase/
  migrations/         مخطط قاعدة البيانات بالترتيب (RLS + دوال الحساب)
  functions/          create-user (إنشاء مستخدم)
  tests/              اختبار تكاملي للصلاحيات والأرصدة (SQL، بيتراجع دايماً)
scripts/              فحص المعمارية
docs/                 شرح المعمارية ودليل إضافة موديول جديد
```

**القاعدة الأساسية:** الصفحات والمكونات **مبتكلمش Supabase مباشرة**. أي قراءة أو كتابة بتبقى دالة في `src/lib`، والصفحة بتناديها. `npm run architecture:check` (وCI) بيفشل لو القاعدة اتكسرت.

- كل الأرقام بتتحسب في قاعدة البيانات (`dashboard_summary` و`project_summaries`...)، والواجهة بتعرضها بس.
- الكتابة حسب الصلاحيات (RLS): أدمن، مالك، ومستخدم بصلاحية `عرض` أو `تعديل` لكل صفحة.
- القيود بتستنى موافقة الأدمن، وأي تعديل بيتأكد إن القيد ماتغيرش في الأثناء (`rev`).
- التقرير بيتطبع من المتصفح (A4)، والإكسل بيتبني في المتصفح وبيتحمّل وقت الاستخدام بس.

لتفاصيل أكتر: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md). ولإضافة صفحة أو موديول جديد: [`docs/ADDING_A_MODULE.md`](docs/ADDING_A_MODULE.md).

## طريقة العمل على أي تعديل

1. افتح فرع جديد (`git checkout -b feature/اسم-التعديل`).
2. عدّل، وشغّل `npm run quality` لحد ما يخضر.
3. ارفع الفرع وافتح Pull Request. **CI** بيشغّل نفس الفحوصات تلقائياً.
4. ادمج لما CI يبقى أخضر.

**التحديثات التلقائية:** Dependabot بيفتح كل سبت Pull Request واحد بتحديثات المكتبات الصغيرة، وPull Request منفصل لكل تحديث كبير. CI بيفحصهم قبل ما تدمجهم. التحديثات الكبيرة (مثل نسخة جديدة من Node أو TypeScript) راجعها بنفسك قبل الدمج.

## قاعدة البيانات

الـ migrations بتتطبّق على مشروع Supabase بالترتيب. الاسم: `YYYYMMDD_NNN_وصف.sql` (الرقم NNN بيكمّل من آخر واحد). مفيش migration بتتعدّل بعد ما تتطبّق: أي تغيير يبقى migration جديدة. تفاصيل القيم السرية (مفاتيح الإشعارات) بتتحط يدوياً في `private.push_config` ومبتتحفظش في git.

## النشر

GitHub Pages من فرع `gh-pages` (مخرجات `dist`). الدمج في `main` **مش بينشر** الموقع لوحده: النشر خطوة منفصلة بتتعمل بعد مراجعة التعديل.
