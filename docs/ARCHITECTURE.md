# معمارية المصباح

## الصورة الكبيرة

```
المتصفح (PWA)                                     Supabase
┌──────────────────────────────────────────┐     ┌────────────────────────────────┐
│ pages/ + components/   ← الشاشات          │     │ Postgres + RLS                 │
│        │  (مبتعرفش Supabase)              │     │  • الجداول والصلاحيات          │
│        ▼                                  │     │  • دوال الحساب (rpc)           │
│ lib/    ← كل قراءة وكتابة وحسابات         │ ──▶ │  • الموافقات والحذف الناعم     │
│        │                                  │     │ Realtime  ← تحديث لحظي         │
│        ▼                                  │     │ Edge function: create-user     │
│ lib/supabase.ts  ← العميل الوحيد          │     └────────────────────────────────┘
└──────────────────────────────────────────┘
```

## الطبقات والقواعد

| الطبقة                         | مسؤوليتها                                                  | مسموح لها تستورد                  |
| ------------------------------ | ---------------------------------------------------------- | --------------------------------- |
| `src/pages`, `src/components`, `src/layout` | الشكل والتفاعل فقط                          | `src/lib`, `src/auth`، ومكوّنات الواجهة |
| `src/lib`                      | قراءة/كتابة البيانات، الحسابات، التنسيق، تصدير الإكسل     | `lib` نفسها فقط (**مش** الواجهة)  |
| `src/auth`                     | الجلسة والـ profile والصلاحيات (الاستثناء الوحيد اللي بيستخدم Supabase خارج lib) | `lib`        |

القاعدتين دول بيتفحصوا تلقائياً (`npm run architecture:check` وCI). الفكرة: لو جدول اتغيّر، بتعدّل ملف واحد في `lib` مش 10 صفحات، والحسابات بتتختبر من غير شاشة.

### شكل دالة البيانات

الدالة في `lib` بترجّع نفس نتيجة Supabase (`{ data, error }`) وبترجّع `null` في الحالات اللي لازم فيها كل-أو-لا-شيء (مثل `fetchPaged`: لو صفحة واحدة فشلت، الكل يفشل ومنعرضش قايمة ناقصة). رسالة الخطأ للمستخدم بتتحدد في الصفحة، مش في `lib`.

```ts
// src/lib/banks.ts
export const saveBank = (row: BankInput, id?: string) =>
  id ? supabase.from('bank_accounts').update(row).eq('id', id) : supabase.from('bank_accounts').insert(row)

// src/pages/banks/BankDialog.tsx
const { error } = await saveBank(row, bank?.id)
if (error) return setError('ما اتحفظش، جرّب تاني')
```

## الأرقام والفلوس

- **الحسابات الكبيرة في قاعدة البيانات** (`dashboard_summary` و`project_summaries` و`advance_summaries` و`bank_summaries`...). الواجهة بتعرض وبس، فكل الشاشات بتتفق على نفس الرقم.
- **الجمع بالقرش:** `sumMoney` و`toCents` (في `lib/money.ts`) بتجمع بالقروش عشان ميظهرش `0.1 + 0.2 = 0.30000000000000004` في تقرير.
- **القراءة على صفحات:** الـ API بيرجّع 1000 صف كحد أقصى، فالقوايم الطويلة بتتقرا بـ `fetchPaged`.

## الصلاحيات والموافقات

- **الأدوار:** `admin` (كل حاجة، وهو الوحيد اللي بيوافق) و`owner` (كل الصلاحيات ما عدا الموافقة، وقيوده بتستنى موافقة الأدمن) و`user` (صلاحية `view` أو `edit` لكل صفحة).
- **الصفحات (الموديولات):** معرّفة في `src/auth/permissions.ts` (`MODULES`)، ومتحقق منها في قاعدة البيانات (جدول `user_permissions` + دوال `private.can_view` و`private.can_edit` جوه سياسات RLS). **الواجهة بتخفي بس، القاعدة هي اللي بتمنع فعلاً.**
- **العهد:** المستخدم بيشوف العهد المسموحة له بس (`user_advance_access`).
- **التسجيل:** مقفول. الأدمن بينشئ الحسابات من `create-user` (Edge Function)، والإيميل لازم يكون في القايمة المسموحة.
- **الموافقة:** القيد بيتسجّل `pending` ومبيتحسبش في الأرقام إلا لما الأدمن يوافق. الموافقة بتتم على نفس النسخة اللي اتعرضت (`rev`)؛ لو القيد اتعدّل في الأثناء، العملية بتتخطى وبتتعرض كـ "اتغيّر" مش كخطأ.
- **الحذف:** ناعم وبسبب إجباري. القيد المحذوف بيفضل ظاهر ومتعلّم لكنه بره كل التقارير والإجماليات، وليه سجل (`entry_history`).

## التحديث اللحظي

`lib/live.ts` بيسمع على جداول قاعدة البيانات (Realtime) ويطلق حدث `data-changed`. الـ hook `useAsync` بيسمع للحدث ويعيد التحميل بصمت (من غير شاشة تحميل)، فأي صفحة مفتوحة بتتحدث لوحدها. دفعة تغييرات (مثل الموافقة على قيود كتير) بتعمل تحديث واحد.

## التقارير

كل تقرير بيتوصف بـ `Section` و`Col` (في `lib/tableTypes.ts`): عناوين الأعمدة ونوعها (نص / فلوس / تاريخ / رقم) والصفوف والإجمالي. نفس الوصف بيتعرض في **الشاشة** (`DataGrid`) وفي **الطباعة** (A4) وفي **الإكسل** (`exportTableExcel`). فلو أضفت عمود، يظهر في التلاتة.

- **الإكسل** بيتبني في المتصفح، ومكتبة `exceljs` بتتحمّل وقت التصدير بس (مش مع الصفحة).
- **النسخة الاحتياطية** (`lib/backup.ts`) بتقرا كل الجداول (بما فيها المحذوف) وتطلع ملف إكسل واحد بأسماء بدل الأكواد، وبتتسجّل.

## الواجهة

- **التوجيه:** hash routing (`#/projects/...`) فيشتغل على GitHub Pages من غير إعداد سيرفر. الصفحات الكبيرة `lazy` عشان التحميل الأول يبقى خفيف.
- **PWA:** `vite-plugin-pwa` + `public/push-sw.js` للإشعارات على الموبايل.
- **الثيم:** فاتح وداكن بمتغيرات CSS في `src/index.css`.

## قاعدة البيانات

- كل تغيير = migration جديدة في `supabase/migrations` (ما بتتعدّلش بعد التطبيق).
- `src/lib/database.types.ts` ملف **مولّد** من المخطط (مستثنى من Prettier). بعد أي migration جدّده بـ `supabase gen types typescript` أو من لوحة Supabase.
- `supabase/tests/rls_and_totals.sql` اختبار تكاملي للصلاحيات والأرصدة: بيعمل مستخدمين مؤقتين وبيتراجع دايماً.
- كل دالة `SECURITY DEFINER` عليها `search_path` ثابت. والدوال اللي التطبيق بينادي عليها (rpc) صلاحية التنفيذ مسحوبة فيها من `public` و`anon` وممنوحة لـ `authenticated`، وبتفحص الصلاحية جواها (`private.is_admin()` أو `private.can_view(...)`). أي دالة جديدة من النوع ده لازم تتبع نفس القاعدة.
